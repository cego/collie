Closes #302.

Before this change, the measurement-tree sweeper judged a tree only by whether its Run had ended. A `collie measure --run` under an already-`failed` Run therefore lost its 1.6 GB base tree to the host's periodic sweep mid-prepare, and ended `Unjudged` after about 15 minutes of Machine time. Now the sweeper's removal makes a single claim on the Machine lock, which `measure` holds for the whole Measurement, and keeps the tree with "a Measurement is running on this Machine" when the lock is held. Judging only checks the lock, without claiming it, so a dry-run `collie cleanup` lists the tree as kept too. A lock left by a dead process is broken, so a crash pins nothing. `collie measure` still accepts an ended Run, because #301's recovery relies on that. `measure` and the sweeper share one helper for the lock's path, `machineLockOf`, and `docs/cli.md` (`#measure`, `#cleanup`) says when a tree is kept.
