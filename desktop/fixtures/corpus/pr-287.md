Three behaviour-preserving refactors that give run-db617d07's tickets one place to change each:

- **A running Check is finished from what is written beside its record**, not only from the memory of the host that spawned it. Before the spawn, the host writes what finishing needs to `check-output/<id>.json`. While the Check runs, it keeps the last 16 KiB of each stream in memory, and writes that to `check-output/<id>.stdout` and `.stderr` when the stream ends. The host that ran a Check finishes it from its own copy, and any other host can finish it from the files. This is the seam #264's adoption builds on.
- **One decision, `outOfReach(view, machine, scope)`, says whether a Run is reachable from the caller's scope.** `run show`, `run wait`, locating a Run and the paired-Machine paths all go through it, so #265's rule and refusal code land once.
- **One benchmark plan decoder, which a workflow can call.** tune-up and the host decode a plan the same way, so #266's plan step can fail with the host's own reason.

The three ship together on this branch, though the spec asked for one merge request each.
