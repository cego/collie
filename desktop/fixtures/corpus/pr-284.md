Reviewers kept re-running commands the builder had recorded minutes earlier on the same commit. Each rerun took minutes and gave the result already on record. The review prompt asked them not to, but `collie verify` enforced that only for a Run's Checks.

Now `collie verify` answers a command that is not a Check from the record it already holds of it on this tree, instead of running it again. A record answers only where all of these match: the executable as resolved, the arguments and the directory; `--name` and `--expect`; the tree; and the environment, collected by this host since it started. The latest such record must have passed or failed: an `unstable` record, or a gate's rerun of one failed test, answers nothing. The answer says `not run again: verification <id> …`, exits with the record's exit code and returns `ran: false`. `--again` runs the command anyway, for a suspected flake, and never runs a Check. `docs/cli.md`, `workflows/review.md` and ADR-draft-a-runs-checks-are-run-by-its-gate (D3 changed, D5 added) describe the rule.
