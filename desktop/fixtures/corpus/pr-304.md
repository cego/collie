When an agent's Output is still unusable after its one repair, the Run now parks at that Step instead of ending `failed`. The park says which file to correct and what the schema rejected, and raises `needs-you`. A resume reads the file again: if it decodes now, the work goes on with no new launch. If it is still unusable, the same agent gets exactly one more repair, and if that fails too the Step parks again. A list parks at its failing item and carries on from it. Before this, a Run that had already done most of its work was lost because of one malformed file that a human or the agent could have fixed in a minute. The `output-unusable` notification kind is gone, and a settings file that still names it loads unchanged.
