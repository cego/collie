A stopped Run stayed under **Needs you** even though the stop worked. The stop sets the Run and its descendants to stopped, but leaves the question the Run was parked on open in the engine, so a resume can ask it again. `factsOfView` (`src/runs.ts`) copied that open question into `asking` whatever the Run's state. Every reader trusts `asking`:

- the board's card, where a decision outranks stopped: Desktop, the TUI and `collie_herd`;
- `attentionFor`, which offered "answer";
- `run show`;
- the Flow view's Answer button.

This was not a cache or refresh problem. The pilot card's `next` came from an older Run on the same Task, `run-db466dfb.implement`. It was stopped from Desktop without its question ever being answered. It was not the Run whose question the human answered.

The fix: a Run that has ended (stopped, failed or succeeded) asks nothing and marks its questions closed. Each question stays listed and unanswered, so the history is kept, and a resume asks it again. The Flow draws an undeclared question on an ended Run as stopped or failed, with no Answer. `docs/using.md` says so under Needs you.
