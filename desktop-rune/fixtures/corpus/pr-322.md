A Task can now hold several merge requests, and Collie treats each one separately. A plan's tickets are grouped into Changes per repository, and each Change opens its own merge request, stacked where the plan says so. Each merge request is identified everywhere by one MR id (`host/path!n`). The board, record, Flow, TUI, MCP and Desktop show one entry per merge request, deduplicated across Machines. Every action names the merge request it acts on. A merge stops only the work on that merge request. A set of merge requests can be released or staged together, in forge-stack and plan-wave order. Before this, a Task carried a single merge request: a multi-repository fan-out showed an empty card, and one merge stopped the whole Task.
