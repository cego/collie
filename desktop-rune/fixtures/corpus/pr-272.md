Collie Desktop's Settings page showed two vertical scrollbars, one for the Settings area and one for the whole window. The hidden (`sr-only`) radio inputs inside Settings' choices are absolutely positioned. Their containing block was the page section that is drawn over the board, not the Settings scroll area, so they spilled out of it and made the window 6–8k px tall. Keyboard focus on a choice also scrolled the whole app off screen. This change adds `relative` to the Settings scroll area so those inputs stay inside it. A new test, `test/desktop-settings-scroll.test.ts`, keeps Settings to one positioned vertical scroll area.

I rendered it in Chrome over CDP, using the built view without Desktop's main process:

| Window | Window height, scrollbar (before → after) | Window scroll after focusing a choice (before → after) |
|---|---|---|
| 1440×900 | 6471px, 15px → 900px, none | 957 → 0 |
| 1024×700 | 7039px, 15px → 700px, none | 1417 → 0 |
| 760×560 | 8683px, 15px → 560px, none | 1829 → 0 |
