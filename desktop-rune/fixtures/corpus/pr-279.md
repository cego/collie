## What changed and why

A verification used to be bound to a fingerprint that included the commit. So a check that passed on uncommitted edits stopped counting the moment those exact bytes were committed. The Run then parked as unproved, or its last fix halted with `fix_unverified`. This change binds each verification to the bytes it ran on.

- **The fingerprint is the content.** It is the Git tree `git add -A` would write, built through a scratch index so the checkout's own index stays as it was. Untracked files and edited submodules are included.
- **Equality goes through one rule.** Every comparison now uses `sameTree`. A tree over the size cap (`TOO_LARGE`), or one git cannot stage (`UNMEASURED`), is never the same tree as anything, itself included.
- **A CI job's pass still needs its own commit.** It also has to match the head it ran on.
- **The last fix leaves a stale check to the gate.** A check that only passed on an earlier tree, or one of the Run's Checks with no record yet, is left to the gate, which runs it on the final tree anyway. Its attestation counts only the checks that passed on this tree.

ADR-0010 and ADR-0023 are amended. CONTEXT.md and the docs for steering, the CLI, the SDK and workflows are updated to match.
