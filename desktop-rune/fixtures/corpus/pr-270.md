A resume asked from Desktop never landed. The host took 45–48 s to resume a Run. Desktop gives each attempt 30 s, and a cut client interrupted the host's handler, so nothing was recorded and the Run stayed parked. Two changes on the host fix this:

- **An admitted control runs to its end.** Once the host takes a stop, hold or resume under a request id, it runs that control in its own scope. A client that stops waiting ends only its wait, not the work. A repeat under the same request id while the first is running joins it and gets its result. This lands `ADR-draft-an-admitted-control-runs-to-its-end` and a sentence in `docs/cli.md`.
- **A resume recovers only the Runs it reaches**: the resumed Run and its descendants. Before, a resume ran the whole herd's recovery pass, which cost about 2 s for each other suspended Run with an answered question. Another Run on a module that a resume registers again is held at its start, untouched, until its own resume or a `recover`. A resume that releases such a hold returns once that Run has settled at its question.
