`hc-pin.json`'s version is now the minimum hc Collie needs, not an exact match. Before this, `collie doctor` failed any hc that wasn't exactly the pinned version, newer ones included. Placing a release ran `herdr-core update --from` the carried hc whenever the last-placed archive differed, which could downgrade an hc the human had upgraded. Both now go through `hcMeets` in `src/hc-install.ts`:

- An hc at or past the pin by semver precedence passes doctor and is left alone on upgrade.
- An hc that is older, or names no valid semver version, fails doctor with the pinned installer as the fix. On upgrade it is updated to the carried hc, which stays the deterministic fallback.
- A prerelease orders below its release, and build metadata is ignored.

The core `hello`, Herdr 1, contract and probe checks are unchanged. `docs/cli.md`, `docs/using.md`, the hc ADR draft and the pin's comment now say minimum.
