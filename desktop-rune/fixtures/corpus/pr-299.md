When a human messages a Run's agent directly while the Run waits on a question, Collie now supersedes that question instead of waiting on it. The message can come from the board, Desktop, `collie run steer`/`deliver`, chat relaying the human's own words, or typing in a Claude pane. While the agent works, every surface shows the card as Working. A stale answer is refused, except from an agent the human messaged. When the messaged agents finish, a Workflow question is asked again (`<root>.r<n>`), but only if nobody answered it and the Workflow still waits on it. An agent's own question is closed instead. Superseding is durable and audited, it survives a restart (including a host that died between herdr taking the message and the supersede being written), and it never stands in for consent: it picks no option, lifts no Hold and undoes no stop. Before this, in run-28de56a3, the plan menu stayed `needs-you` while the planner was rewriting the plan, and answering it would have started `implement` on a plan still in flux. The decisions are in ADR-draft-a-humans-message-supersedes-a-runs-open-question.
