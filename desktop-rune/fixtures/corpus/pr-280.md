A release whose merge request another merge leaves conflicting with its target used to fail. It failed when the forge refused the merge after the go, and it also spent fix rounds on a CI job that never ran. Now it waits. A conflicting merge request names the conflict instead of `is not in its pipeline`, and the release parks on a repair line before it takes or checks any conflicting head. Once its branch has taken the target, the release fast-forwards to the new head, proves it and asks for a fresh go. A merge the forge refuses while the review still reads ready still fails. After every conflict wait the release fast-forwards, so a checkout with changes the merge request does not carry is still refused.
